1. Feature Attribution (Vertex Explainable AI)

24 Words
Measures how much each input feature contributed to a model's prediction using Sampled Shapley (tabular), Integrated Gradients (differentiable neural nets), or XRAI (image regions).
  • Q#88 (Ans A) Using Sampled Shapley in AutoML Tables to see which features drove credit card default predictions.
  • Q#227 (Ans A) Using Sampled Shapley to explain TensorFlow neural network credit risk decisions for banking regulators.
  • Q#235 (Ans D) Aggregating Vertex Explainable AI feature attributions across an image dataset to identify model bias.
  • Q#275 (Ans A) Configuring Sampled Shapley (path_count=5) on an XGBoost endpoint for low-latency online explanations.
  • Q#301 (Ans B) Using Vertex Explainable AI feature-based explanations for transparent loan approval and credit limit decisions.

2. Training-Serving Skew

Needs Training Data
Occurs when live production inputs differ from the original training dataset baseline—caused either by inconsistent preprocessing code between training and serving, or shifted real-world data.
  • Q#173 (Ans B) Receiving a Vertex AI training-serving skew alert, retraining on recent data, and updating the monitoring baseline.
  • Q#211 (Ans D) & Q#263 (Ans C) Running TFX (tf.Transform) on Dataflow to materialize TFRecords and embed transform_fn inside the SavedModel.
  • Q#289 (Ans B) Putting feature engineering inside BigQuery ML's TRANSFORM clause so identical transformations run automatically at serving time.
  • Q#325 (Ans A) Troubleshooting a sharp production AUC drop in a churn model by monitoring training-serving skew on endpoint requests.

3. Attribution & Prediction Drift

Rankings Shift
Occurs when feature importance (attribution) or predicted output distributions shift over time—meaning the model begins relying on different features or feature interactions than before.
  • Q#274 (Ans A) Monitoring feature attribution skew/drift on a tabular regression pipeline to trigger automatic retraining.
  • Q#275 (Ans A) Creating a Vertex AI Model Monitoring job for prediction/attribution drift on an online XGBoost model.
  • Q#291 (Ans D) Setting up feature attribution drift monitoring (sampling_rate=0.1) to catch shifts in hospital patient feature interactions at low cost.
  • Q#318 (Ans A) Alerting on model_monitoring_anomaly in Cloud Logging + viewing attributions in the Vertex AI Console (Hard GCP Rule: request-response logging CANNOT be enabled when Model Monitoring is already active!).

4. Feature Drift (Data Drift)

No Training Data Needed
Occurs when the statistical distribution of live production input features changes over time compared to recent production traffic—ideal when the original training dataset is unavailable.
  • Q#30 (Ans A) A DNN regression model degrades 6 months after deployment because current production input values shifted from historical distributions.
  • Q#120 (Ans A) Comparing daily incoming feature statistics against a 30-day rolling average to catch silent third-party data changes.
  • Q#188 (Ans A) Using feature drift detection (instead of skew) for a third-party bank model where training data is unavailable.
  • Q#190 (Ans C) Lowering sample_rate in RandomSampleConfig to cut feature drift monitoring costs on a high-traffic endpoint.
  • Q#227 (Ans A) Enabling Vertex AI Model Monitoring to track feature distribution drift on a deployed credit risk model.

5. Concept Drift vs. Data / Target Leakage (Grounded Corrections)

A. Concept Drift (20 words)

The real-world relationship between inputs and the target label changes over time (e.g., new seasonal trends, pandemics, or fraud tactics).
  • Q#174 (Ans D) Retail sales model degrades as buyer behavior shifts monthly; solved by scheduled monthly retraining pipelines.
  • Q#223 (Ans B) Flu prediction model fails during a new pandemic wave; schedule a monthly batch Vertex AI Pipeline via Cloud Scheduler aligned with monthly national flu labels (never a 24/7 online endpoint!).
  • Q#317 (Ans B) Financial fraud model degrades as fraudsters invent new patterns; solved by continuous automated retraining.

B. Data / Target Leakage (22 words)

Future or target-derived information accidentally leaks into training features or splits, causing unrealistically high training accuracy (~0.99 AUC) but poor production performance.
  • Q#18 (Ans D) Performing a manual split with a 30-day buffer gap across multiple time-signal columns so a 20-day LTV lookahead window never leaks (AutoML's Time column accepts only 1 column with 0 gap!).
  • Q#48 (Ans C) Achieving 0.99 untuned training AUC ROC immediately diagnoses target leakage—remove features highly correlated with or derived from post-outcome events.
  • Q#36 & Q#76 (Ans B) Computing scaling stats before splitting (Q#36) or running random CV on time-series (Q#76) leaks test/future distributions.
  • Q#53 (Ans B) & Q#184 (Ans A) Group-splitting by Author ID (Q#53) or store name (Q#184) when predicting for unseen authors or unseen retail stores.

1 Attaching 3 NVIDIA Tesla V100 GPUs to a Vertex AI N1 training VM Invalid GCP GPU count! N1 VMs support only 1, 2, 4, or 8 V100s. Upgrade to 24 vCPUs + 1 V100 GPU (Ans C) to fix CPU preprocessing starvation. Q#338
2 Training Vertex AI AutoML Tabular / Forecasting on < 1,000 rows (e.g., 365 daily rows) Hard GCP validation failure! AutoML strictly requires ≥ 1,000 rows. Train a BigQuery ML Regression model (Ans A) instead. Q#207
3 Enabling Request-Response Logging on an endpoint that already has Model Monitoring active Hard GCP mutual exclusion! Model Monitoring already logs payloads to BigQuery. Alert via Cloud Logging + Vertex AI Console (Ans A). Q#318
4 Re-scanning hundreds of millions of BigQuery rows per epoch in custom TensorFlow Causes massive gRPC I/O bottlenecks and skew risk. Run TFX (tf.Transform) on Dataflow → sharded GCS TFRecords (Ans C). Q#132 Q#263
5 Training supervised ML on synthetic z-score heuristic labels when 0 failure labels exist Violates Rules of ML Rule #1 (learns heuristic noise). Deploy & evaluate the live heuristic first while collecting real incident labels. Q#94 Q#139
6 Estimating Recall (TP / (TP + FN)) solely from model-flagged comments Unflagged FNs are never observed! Route an unbiased 0.1% random sample of raw comments to human moderators (Ans C). Q#85
7 Deploying a 24/7 online Vertex AI Endpoint for monthly/weekly batch jobs or monthly labels Wastes 24/7 compute. Schedule a Batch Prediction / Cloud Scheduler pipeline matching ground-truth cadence. Q#223 Q#255
8 Switching job config to a TPU v3-32 pod without adding tf.distribute.Strategy code Single-device TF code cannot distribute across multi-chip TPUs/GPUs automatically. Refactor with tf.distribute.Strategy (Ans D). Q#96
